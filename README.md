# holddrag — 长按拖窗 HoldDrag

[![Platform](https://img.shields.io/badge/platform-Windows%207%2B-0078D6)](#)
[![.NET](https://img.shields.io/badge/.NET-10-512BD4)](#)
[![License](https://img.shields.io/badge/license-GPL--3.0-blue)](#许可证)

**长按一个自定义按键，随手拖动 / 缩放 / 操作光标下的任意窗口。**

按 `Enter`（可改成任意键或鼠标侧键）不要松手，光标底下那扇窗四周就会亮起一圈外框；
这时按住鼠标左键就能把它拖走 —— **不用去找标题栏，全屏窗口也能拖**。

> 上游来源：本项目派生自 [stefansundin/altdrag](https://github.com/stefansundin/altdrag)（AltDrag，GPL-3.0）。
> 上游的 C 源码**不在当前仓库里**；这里保留的是**独立的 C# / .NET 10 实现**
> [`holddrag/src/`](holddrag/src/) 与启动器 [`launcher/`](launcher/)。

## v1.10.2 修复（2026-11-04）：激活瞬间被自己复位（核心功能失效）

**症状**：按住触发键，外框闪一下就没了，鼠标完全拖不动窗口。

**根因**：激活时会做一次「就地重装鼠标钩子、抢占钩子链头部」，而这次重装也广播了
`HooksReinstalled`；订阅方按「钩子出过事 = 事件丢失」处理，立刻 `Trigger.Reset()` ——
于是刚激活就被复位，外框被兜底收掉，后续鼠标按下全部按「未激活」放行。

**修复**：`ReinstallMouseOnThisThread`（抢占链头，一瞬间完成、不丢事件）不再广播
`HooksReinstalled`；只有 `Reinstall()`（看门狗救援，真的会丢事件）才广播。
TrayContext 里重复注册的第二个订阅也一并去掉。

## v1.10.1 紧急修复（2026-11-04）：系统级"左键一直按着"

**症状**：用户根本没按左键，但整个系统都处在"左键按下"状态 —— 点一下就开始拖选、窗口跟着光标跑、松开也没用，重启程序不管用（状态在系统里，不在程序里）。

**根因**：触发键**短按**（长按阈值内松开）时，程序会把阈值期间被吞掉的鼠标按下**只补一个 down** 还给下层，设计上依赖"用户真实的 up 稍后送达"来配对。这个 up 一旦丢失 —— 看门狗重装钩子的缝隙、暂停、改配置、UAC 安全桌面、程序退出 —— 那个合成 down 就永远没有配对的 up，Windows 的按键状态里从此留着一个"按着"的左键。

**修复**（核心就是给合成按下记账，保证一定有归还路径）：

| 时机 | 动作 |
| --- | --- |
| 注入"只按下" | 记进 `_injectedDownMask` |
| 真实抬起到达 | 销账（不会再补第二次 up） |
| 钩子重装 | 三本账清零 + 立刻补发欠着的 up |
| 暂停 / 改配置 / 退出 | 立刻补发欠着的 up |
| 每 500ms 巡检 | 系统已不是按下 → 只销账；仍按着但早已不该按着（无拖动、触发键也没按）→ 超过 8 秒补发 up |

**已经卡住怎么自救**：物理点一次左键（按下再松开）即可清掉系统里的残留状态；升级后不会再发生。

**同时**：自检总超时 150 → 240 秒（用例变多后 150 秒会把"机器慢"误报成"卡住"）；新增 T102 锁住这条归还路径。

## v1.10.0 改了什么

### 1. 新功能：点按切换模式

「触发方式 → 触发模式」新增两个选项：

| 模式 | 行为 |
| --- | --- |
| **长按**（默认） | 按住触发键才接管，松手立刻退出——和以前完全一样 |
| **点按切换** | 点一下抓住，再点一下放下；**不用一直按着键**（此时触发键不再输入字符） |

出厂默认仍是长按，老配置升级后行为不变。配套自检 T101 锁住状态迁移。

### 2. 修复（都是有具体复现路径的真问题）

**更新 / 重启链路**

- 更新完可能**一个进程都不剩**：替换后立刻拉起新进程，而"点击确定后退出"的对话框还在等用户点。
  用户发呆超过 30 秒，新进程就因等不到单实例锁而让位，随后旧进程退出 → 托盘空了。
  现在**先问、再替换**，并且新进程带 `--take-over` 等旧进程释放锁。
- 提权重启 / 托盘「以管理员重启」有同样的坑，同样改为 `--take-over` 接班。
- 下载到的不是程序（热点/代理把资产换成了 HTML 错误页）也会被搬到正式文件名上：现在下载后与替换前都校验 **MZ + PE 签名**。
- 新版本启动失败时不会再把用户的程序留在"半新半旧"状态：自动回滚成旧版。
- 下载卡死时「取消下载」其实点不动（`Read` 不返回就检查不到令牌）：改成可取消的异步读 + 60 秒无进展超时。
- `--checkupdate` 在英文界面下**永远返回 0**（退出码靠中文字符串前缀判断），脚本化诊断失真：改为显式失败标志。

**第二次启动 / 单实例**

- 只是再点一次图标想打开设置，也会先弹 UAC（提权判定排在单实例判定之前）：现在**先探测已有实例**，有就直接唤起设置窗口并退出。
- 看门狗重装钩子后 `_hookQuit` 没被置位，队列里的重装消息会把鼠标钩子装到一条即将退出的线程上，导致"拖动彻底失灵而日志看起来正常"。

**触发键状态机**

- 松开事件丢失（开始录制按键、暂停、钩子重装、UAC 安全桌面）会让 `_held` / `Active` **永久卡住**：
  之后触发键失灵，或者每次点鼠标都在拖窗口。新增 `Reset()` 并在上述路径调用。
- 长按计时器在 ThreadPool 线程上判断 `_held`，与钩子线程竞争，可能"手已经松了还激活"；
  回调里抛异常还会直接终结进程。现在状态迁移统一加锁 + 代次校验 + 异常兜底。
- 暂停/抑制时的早退分支只清了两个标志，残留的 `_bufferedDown` / `_swallowUp` 会吃掉后面一次抬起。

**拖动 / 外框**

- 空闲 15 秒释放外框缓冲区之后，同尺寸窗口不再重建外框（停在上一扇窗上）：尺寸缓存现在会一起失效。
- 换缓冲区时直接删除旧 HBITMAP，可能删掉在途 `UpdateLayeredWindow` 正在读的内存：改为"退休队列"，落地后统一释放。
- 拖动线程对浮层做同步 `SetWindowPos`，与界面线程形成锁反转：改为 `SWP_ASYNCWINDOWPOS`。
- 目标窗口不可缩放（无 `WS_THICKFRAME` 的固定对话框）也会被右键拖变形：现在直接放行不接管。
- `WM_ENTERSIZEMOVE` / `WM_EXITSIZEMOVE` 不成对：取消拖动时目标窗口一直以为自己还在拖动循环里；
  结束通知还可能早于最后一帧几何写入，导致程序存下错误位置。现在成对且在最后一帧之后。
- 15 秒空闲释放用的是 `WinForms.Timer`，但它是在钩子线程上创建的、那条线程从不 `DispatchMessage`，
  于是**永远不会触发**（文档承诺的内存回收是死代码）：改用线程池计时器。
- 只用一条边缩放时会顺带改掉另一条边（<112px 宽的窗口被莫名撑宽）。
- `WM_SIZING` 最小尺寸探测每帧都做一次跨进程同步消息：现在探到"没有最小尺寸限制"就整场不再问。
- 帧间隔 7ms（144Hz）在默认 15.6ms 定时器精度下做不到：拖动期间 `timeBeginPeriod(1)`，结束立即还原。

**配置**

- 「保存并生效」之后 `_edit` 变成了**正在生效的那份配置对象**，于是"保存后点取消"仍会改到运行中的设置；
  写盘失败时内存也会被替换成没落盘的版本。现在保存的是副本，失败则保持原样、不广播变更。
- 主配置损坏 → 从备份恢复 → 立刻保存，会把**仍然可用的 `.bak` 覆盖成坏文件**；现在只轮换能解析的文件。
- 未知字段（新版本写入、旧版本打开）会被静默丢掉：加 `[JsonExtensionData]` 原样带回。
- 写盘改为"临时文件 + `Flush(true)` + 原子替换"，失败时清掉 `.tmp`。
- 刷新频率填 5 会按 20 跑但界面还显示 5：输入即吸附到 20，保存后回填规范化后的值。

**开机自启**

- 关闭自启时不管 `schtasks` 成没成功都报"已保存并生效"：现在删完再查一遍，删不掉就明确报错。
- `schtasks` 的 stdout/stderr 先读完再等退出，管道写满就会**把 UI 线程卡死**（8 秒超时形同虚设）：改为异步读 + 超时杀进程树。

**设置窗口**

- 「外框 → 粗细 / 圆角 / 不透明度」三个输入框注册到了**上一张卡片**上：那三个框没有底板，
  宽窗口下还会在外框卡片上画出三个幽灵白块。
- 录制按键时输入框底色写死浅黄，暗色主题下浅色字落在浅黄底上几乎看不见（1.1:1）。
- 英文文案被固定宽度截断（`Check for upd…` / `Choose progr…`）：按钮宽度按文字实测。
- 字体/工具提示在每次 DPI/主题/语言重建时泄漏 GDI 资源；关闭顺序还会重复 Dispose。
- 禁用态有四种画法：下拉框/数字框/开关/自绘控件现在统一走 `DisabledFill/DisabledStroke`。
- 键盘不可用：没有 Enter/Esc，Tab 会停在色板、缩略图、帮助手风琴这些"只认鼠标"的控件上。
  现在 Enter = 保存并生效、Esc = 取消，纯鼠标控件退出 Tab 顺序（同卡片的下拉框是它们的键盘入口）。
- 英文界面里的中文标点（`（…）`、`。`）与 `\"No\"` 双重转义：统一由 `Loc.Open/Close/InParens` 出括号。
- 托盘菜单里两行状态文案没走 `Loc.T`，English 下永远是中文。

**启动器**

- 同版本缓存被占用时会返回 `HoldDrag.App.exe.tmp` 并用 ShellExecute 启动：`.tmp` 没有关联，
  `Process.Start` **返回 null 且不抛异常** → 双击没反应、连错误框都没有。现在 `UseShellExecute=false`。
- 诊断参数（`--selftest` 等）的退出码以前永远丢失：现在启动器等子进程结束并原样返回。
- 运行时检测只认"存在一个 10.* 目录"，且**拿一个根本不存在的 dll 名**做完整性检查——
  真实安装里没有 `Microsoft.WindowsDesktop.App.dll`，所以每台机器都会被误报"缺少 .NET 10"。
  现在按 `Microsoft.WindowsDesktop.App.deps.json` 判断，并补上 `DOTNET_ROOT_X64`、HKCU、用户级安装目录。
- 解包用固定 `.tmp` + `FileShare.None`：两个实例同时首次启动必有一个报"写不进去"；
  还会"先删后移"，删掉的正是另一个实例马上要启动的文件。现在临时名带进程号、`File.Replace` 原子替换、失败重试。
- 启动器自己没有版本信息（资源管理器里 0.0.0.0）、没有清单（缺运行时的提示窗在高 DPI 下发虚）：都已补上。

### 3. 一致性整理

- 关闭按钮悬停色、录制底色等硬编码颜色收进 `Tokens`。
- 颜色下拉列表用界面字体（`SystemFonts.DefaultFont` 是 9pt 的另一套字体，展开列表比收起状态小一号）。
- 开关的勾选/取消都有补间（以前取消是瞬间跳变）；侧栏每帧少分配一个 `SolidBrush`。
- 下拉框闭合态与输入框同高，同页所有下拉框高度一致。

## 快速开始

1. 到 **[Releases](https://github.com/QQQOrange/holddrag/releases/latest)** 下载最新的 `HoldDrag.exe`，双击运行。
   **会弹一次 UAC 提权确认**（原因见下），点「是」。
2. 托盘区出现图标，首次运行会有气泡提示。
3. **长按 `Enter` 约 0.6 秒不要松手** —— 光标底下的窗口立刻亮起一圈圆角外框，说明它已被接管。
   接着按住左键拖它即可。
4. **双击托盘图标**打开设置窗口。

> 换触发键：设置窗口里点「重新录制」→ 直接按下你想用的键。
> 左 / 右 / 中键已被鼠标动作占用，不能当触发键；鼠标侧键（前进 / 后退）可以。

> **需要 .NET 10 桌面运行时**（框架依赖发布，主程序只有 ~760 KB）。
> 没装也不会看到看不懂的英文报错：双击 `HoldDrag.exe` 时，启动器会先检查，缺了就弹一个中文窗口，
> 点「去官网下载」直接打开 [Windows Desktop Runtime 10](https://dotnet.microsoft.com/download/dotnet/10.0)，
> 也可以「复制链接」自己粘到浏览器；窗口里还会提醒要选 **x64** 的 **Desktop Runtime**（只装 .NET Runtime / ASP.NET Core 不够）。

## 单文件 + .NET 10：怎么既"不打包运行时"又能提示下载

对外**只有一个 `HoldDrag.exe`（约 820 KB）**，它同时干两件事：

1. 用 **.NET Framework 4.8** 写的那一层做启动前检查（Win10 1903+ / Win11 自带，缺 .NET 10 时它也能跑）；
2. 真正的程序（.NET 10，约 760 KB 单文件）**内嵌在这个 exe 里**，检查通过后解包再启动。

```
%LOCALAPPDATA%\HoldDrag\app\<内容哈希>\HoldDrag.App.exe   ← 首次启动自动展开，同版本只解一次
```

| 场景 | 表现 |
| --- | --- |
| 装了 .NET 10 | 解包（首次）/ 直接命中缓存（之后），无任何提示，正常启动 |
| 没装 .NET 10 | 弹出中文窗口：「需要先安装 .NET 10 桌面运行时」+ 官网链接 +「去官网下载 / 复制链接 / 关闭」，**不会启动主程序**（退出码 1） |
| 解包失败（磁盘满 / 无权限 / 杀软拦） | 明确告诉原因，而不是闪退（退出码 4） |
| 诊断参数（`--selftest` 等） | 启动器等子进程结束，**原样返回它的退出码** |

**为什么必须这么绕**：主程序是 .NET 10 应用，缺运行时它连进程都起不来，没机会自己弹窗；
能弹窗的只能是"不依赖 .NET 10"的那一层。要"只有一个文件"，这一层就只能把主程序背在身上。

**更新时替换的是这个单文件本身**：启动器启动时会用 `--host <自身路径>` 告诉主程序"用户手里那个 exe 在哪"，
自动更新按这个路径做「旧 exe → `.old`、新文件 → 正式名」，重启后由新 exe 解包新版主程序并自动清掉旧解包目录。

## 单实例与"接替启动"

**同一时间只允许存在一个 HoldDrag 进程，不能开出好几个。**

- 第二次启动**不会**再驻留成第二个进程，也不会"没反应"：它会把**已在运行的那个实例的设置窗口弹出来**，然后自己退出（退出码 0）。
- 实现：互斥体 `Local\HoldDrag.SingleInstance.v1` + 命名事件 `Local\HoldDrag.ShowSettings.v1`。
- 这两个名字**是契约，不能改**：一改，新旧版本就互认不出来，直接退化成"能同时开出两个"。
- 例外（有意为之）：`--selftest` / `--stress` / `--dragbench` / `--probe` / `--windowhost` 这些**诊断分支**会绕过互斥。
- **接替启动**（`--take-over`，内部参数）：更新、提权重启、以管理员重启都是"新进程先起、旧进程后关"，
  这些实例必须**等**旧进程释放互斥体再接管（最多 60 秒），而不是让位——否则更新完一个进程都不剩。
- 回归保护：自检 **T91** 会**真实启动第二个 exe**，断言它自己退出并唤起已有实例。

## 多语言（v1.9.0 新增）

「启动与权限 → 语言 / Language」里选 **简体中文** 或 **English**：

- **选中即生效**：写进 `config.json` 的 `Language` 字段，并立刻重建整个设置窗口与托盘菜单，不需要重启；
- 覆盖范围：设置窗口全部页面、托盘右键菜单与气泡、所有对话框与提示、更新窗口、按键名、颜色与样式名；
- 实现方式：源码里的中文原文直接当 key（`Loc.T("检查更新")`），译文集中放在 `Loc.cs`；
  查不到就回退中文，**不会露 key、也不会抛异常**。
- 句子里需要括号时用 `Loc.Open` / `Loc.Close` / `Loc.InParens`，否则英文界面会出现「（…）」这种中英混排。
- 调试：`HoldDrag.exe --langshot en` 会按"中文起步 → 用下拉框切到英文"的真实路径走一遍，
  再把每个设置页截图到 `%TEMP%\holddrag-langshot\`，用来核对译文有没有溢出或折行错位。

## 文字渲染（v1.9.1 调整）

- **字号一律用整数像素**（统一 `Sc(px)` → `GraphicsUnit.Pixel`），避免 125% / 150% 下算出小数磅值导致中文字形发毛。
- **字体族按语言挑**：中文用「微软雅黑 UI」，英文用 Segoe UI；不用可变字体。

## 自动更新

「关于」页里有 **GitHub 项目主页**链接、**自动更新**开关和 **检查更新** 按钮：

- **自动更新默认开启**：每次启动后台查一次最新发布，**真有新版本就弹一个独立窗口**（立即下载 / 稍后 / 打开发布页）。
- **下载有专属窗口**：显示百分比与已下载/总大小，带**「取消下载」按钮**——点了就真的中断
  （取消令牌 + 60 秒无进展超时），半截的 `.part` 会被删掉，程序保持当前版本。
- **下载后先校验**：必须是 Windows 程序（MZ + PE 签名），否则判定为被网络替换并给出原因。
- **替换前先确认**：点「确定」才替换并退出，避免"用户发呆导致更新后没有进程"。
- 点「检查更新」同样走这套流程，并在按钮右侧实时回显状态（检查中 / 已是最新 / 发现新版 / 已取消 / 下载失败）。
- 同一个新版本**只提示一次**；网络不通时如实报出具体原因并给出发布页链接，**绝不**谎报"已是最新"。

### GitHub 个人访问令牌（可选）

GitHub 的接口对匿名请求只给 **60 次/小时**。填一个**只读**的个人访问令牌就能提到 **5000 次/小时**：

1. GitHub → Settings → Developer settings → Personal access tokens，创建一个**只读公开仓库**的令牌。
2. 粘到「关于 → GitHub 访问令牌」，点 **验证令牌**（真的向 GitHub 发一次请求）→ 再点 **保存令牌**（立刻生效）。
3. 不确定怎么建？点输入框右边的 **?** 图标。

说明：令牌**明文保存在本机** `%APPDATA%\HoldDrag\config.json`，只用于读本仓库的发布信息；
界面与日志里**只回显是否存在**，不显示令牌的任何片段；令牌失效时自动退回匿名方式并在状态里说明原因。

**维护者注意**：自动更新抓的资产名是 `HoldDrag.exe`（`Updater.AssetName`）——
也就是"启动器 + 内嵌主程序"那个单文件，**不要**上传解包出来的 `HoldDrag.App.exe`。

## 为什么需要管理员权限

- 全局低级键鼠钩子只有在**同级或更高权限**下，才能看到"以管理员身份运行的窗口"上的输入。
- 要移动 / 缩放提权窗口，本进程也必须是管理员。

所以默认开启，但设置里可以关掉。为了不每次开机都弹 UAC，开机自启默认走
**计划任务（最高权限 + 登录时静默启动）**，而不是注册表 `Run` 项。

**UAC 上点了「否」不会启动失败** —— 程序降级成普通权限继续跑，功能照常，
只是拖不动任务管理器这类提权窗口，随后弹一次"是否以管理员重启"，取消后不再打扰。

临时不提权运行：`HoldDrag.exe --no-elevate`

## 触发键的两个关键行为

1. **短按 = 原样透传。** 按下瞬间程序吞掉这次按键并开始计时；在阈值内松手，就用 `SendInput`
   合成一次完整的「按下 + 抬起」补发出去。正常打字、回车换行、回车提交都不受影响。
2. **超过阈值 = 进入激活态。** 此时不再补发任何按键，鼠标左 / 右 / 中键触发对应动作；松开触发键即退出。

**必须知道的代价：** 要区分「长按」和「连发」，就必须吞掉键盘的自动重复事件，
因此**按住 Enter 不放连续换行会被压成一次**。这是原理上的取舍，无法两头兼顾。

## 从源码构建

需要 **.NET SDK 10**（`dotnet --list-sdks` 应能看到 `10.0.x`）。

```powershell
# 1) 先发布主程序（.NET 10 单文件）——启动器要把它内嵌进去
dotnet publish holddrag/src/HoldDrag.csproj -c Release

# 2) 再编启动器（net48）→ 产物就是对外唯一那个 HoldDrag.exe（约 820 KB）
dotnet build launcher/HoldDragLauncher.csproj -c Release

# 3) 拷出来即可发布（只有一个文件）
copy launcher\bin\Release\net48\HoldDrag.exe out\

# 4) 验证"缺 .NET 10"的中文提示（设这个环境变量就假装没装，不会真的去下载）
$env:HOLDDRAAG_FORCE_MISSING_DOTNET=1
.\out\HoldDrag.exe

# 自检（必须先确认桌面上没有旧实例在跑）；启动器会把退出码原样带回来
.\out\HoldDrag.exe --selftest      # 退出码 0 = 全通过

# 压力测试
.\out\HoldDrag.exe --stress
```

> ⚠️ **`%TEMP%` 必须可写**。自检里大量用例会在临时目录建夹具窗口，
> 若临时目录被沙箱 / 权限限制，会出现成片的 "Access to the path ... is denied" 假红。

> ⚠️ **自检必须在"没有旧实例、且桌面未被遮挡"的环境下独占运行**（约 90 秒）。
> 并发跑两份实例会争抢全局光标与前台窗口，产生"期望 90、实际 -1500"这类离谱读数。

## 已知限制

1. **Win11 的 Snap Layouts 布局面板不会弹出。** 要实现双击左键 / 右键就不能用系统的原生拖动循环，
   边缘吸附是程序自己实现的（AltSnap 同样如此）；吸附落点与原生一致。
2. **按住触发键不会连续换行**（见上文取舍）。
3. 用 `Alt` / `Ctrl` / `Win` 作触发键时，按住期间该键的组合功能不可用（如 Win 作触发键时 `Win+E` 无效）。
4. `CapsLock` 作触发键时不会切换大小写（被程序压制）。
5. 极少数自绘界面 / 全屏游戏的窗口可能无法移动或移动异常。
6. 提权窗口只有在本程序也提权时才能操作。
7. **落键次序边界**：若左键按下**早于**触发键 25 ms 以上，那一次按下已真实投递给下层窗口，
   补起时若把起点回溯到按下点会让窗口跳变，故选择"不跳变"→ 丢掉起段位移。**建议：先把触发键落稳，再按左键。**
8. **点按切换模式**下触发键不再输入字符——这是模式语义的一部分，不是 bug。
