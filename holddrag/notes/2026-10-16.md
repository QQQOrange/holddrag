### 三个根因结论

**问题一 — 设置页无法被拖动**
`WindowActions.FindTarget`（解编译 L22379-22410）在 32 次 Z 序遍历中只接受 `lpdwProcessId != OwnPid` 的窗口，本进程窗口被静默跳过（`GetWindow(GW_HWNDNEXT)` 换下一个）；背后只有桌面时返回 0。自检 663 项全绿是因为所有相关用例都设了 `AllowOwnProcessAsTargetForTest = true`，而生产恒为 false。
修复方向：新增 `AllowDragOwnWindows` 配置 + `IsOwnProcessTarget(hwnd)`（允许浮层类 `HoldDragOverlayWindow` / 设置窗口类），或显式放行本进程且类名不在 `ExcludedClasses` 中的窗口。

**问题二 — 粗细参数不生效（三层叠加）**
1. `SettingsForm.StyleGallery.OnPaint`（L14356-14400）把粗细钳死：`int thickness = Math.Min(_thickness, 3);` → 缩略图粗细 3/4/6/8 渲染结果 MD5 完全相同（`c597c139…`），实测 `changedVsPrev=0`。
2. `FrameStyles.MarginFor`（L3814）：描边路径以窗口「可见边缘」为中心，`t/2+1+偏移`，一半线宽被目标窗口及其 DWM 阴影盖住。实测 Dashed/Sky：粗细 6 外露墨量 1266 / 外扩 5px，粗细 8 → 1546 / 6px（仅 +22%）。
3. 外扩模式下 `DragEngine.Step` 设 `_frame.RaiseAboveAll = inset`，`inset=false` 时不置顶，外框被别窗遮挡。日志 `[诊断] 拖动框已请求显示 … 抬到最顶=False`。
> 注：真实外框粗细链路（`ApplyTheme → MarkContentDirty → WM_RETHEME → Rebuild → Push`）经端到端抓屏证明**是生效的**（6→8 时外框 2657x1658 → 2659x1660，+2px）。所以问题在「视觉不可辨」而非「不生效」，必须按三层分别修。

**问题三 — 触发键激活后左键穿透点击**
`Coordinator.OnMouseCore`（L1064-1126）两条放行路径：
- 路径 A：阈值未到（`_trigger.Held && !Active`）时左键按下被放行；随后激活，`HandleButtonDown`（L1322）见 `_passedDown[idx]==true` 便 `PostPairedButtonUp` 补发 WM_LBUTTONUP → 下层窗口收到完整「按下+抬起」= 一次真实点击。日志 `补起拖动` 出现 54 次。
- 路径 B：激活后 `FindTarget` 返回 0 时，按下与抬起**都**放行（设置页场景正是如此，与问题一同源）。
修复方向：引入 `_bufferedDown` 缓冲（HoldMs 窗口内先吞下按下、等阈值判定后再决定重放或丢弃），并在 `_trigger.Active` 时一律吞掉 down/up。

## 追加（第三轮）：同时按 Enter + 左键时「外框出来了但左键毫无反应」

用户报障：**同时按住 Enter（触发键）和左键 → 外框出现（说明已激活），但左键什么都做不了、也拖不动窗口。**
（本轮自会话压缩后续做；代码在 19:08 已落码并通过 Debug 自检，但发布产物与交付目录仍停在第二轮，本次补齐。）

### 两条根因
1. **主因**：阈值期间被缓冲的按下，要等「激活后的第一次鼠标移动」才被 `AdoptHeldButtonIfAny` 收养。
   按下不动的时序（Enter t0 → 左键 t1 被缓冲 → HoldMs 到点 t2 激活、外框亮起 → t3 手不动）里，
   没有任何移动事件 → 收养从未被调用 → `_drag.IsDragging` 恒 false。
   → 新增 `Coordinator.AdoptBufferedButtonsNow(pt)`，在 `OnTriggerActivated` 激活瞬间收养；
     `ShowHoverFrame` 改为仅在未拖动时调用。
2. **次因**：`GroupBox` 的窗口类就是 `BUTTON` → 被 `InteractiveClasses` 误判为可交互控件 →
   设置页成片分组区上的按下被放行给容器（容器不吃鼠标）→ 同样「左键点了没反应」。
   → `IsInteractiveClassName(string)` 改为 **`IsInteractiveControl(nint h)`**，类名匹配 `Button` 后
     追加 `(GetWindowLong(h, -16) & 0xF) == 0x7 (BS_GROUPBOX)` → 判为「非交互」。
   另补 `HandleButtonDown` 里 `Begin` 返回 false 的诊断日志。

### ⚠️ 关键方法教训（务必记住）
**旧 T86 把缺陷写成了预期**：`Check(!Drag.IsDragging, "此刻还没有拖动会话（正是用户看到的状态）")`
—— 缺陷一修这条立刻变红。旧=红即修复生效。复跑/移植时必须倒转该断言（与第一轮那 13 项同类）。

### 顺带修掉两条「环境敏感」假红用例（不改产品语义）
- **T69 不透明度**：旧 `num3 < num2*0.6` 等价于假设背景远比外框暗；外框半透明 → 读数 = `alpha*外框+(1-alpha)*背景`。
  本机壁纸深青（实测 `RGB(4,70,91)` → 青色度 23），三次观测 29/36/46 与 bg=8/23/37 的公式逐项吻合 → 产品正确、阈值写错。
  改为「先量背景 bg」+ 两条断言：`num3 <= int(0.4*num2+0.6*bg)+4`、`num2-num3 >= (num2-bg)/2`。
- **T80**：`SetWindowPos(..., 20u=SWP_NOACTIVATE|SWP_NOZORDER)` 不置顶 → 桌面中心的 Edge 窗口盖住测试窗口，
  命中测试返回 Edge（`FindTarget` 本来就对）。改 `HWND_TOPMOST(-1)+SWP_SHOWWINDOW(0x40)`，并加前置校验：
  命中≠测试窗口 → 明确跳过而非误判产品。

# 第六轮（21:20 收尾）：真凶 = GetAsyncKeyState 漏报，判据改为「钩子事件账本」

## 用户报障（决定性对照）
「按 Enter → 很快按下左键 → 立刻移动」窗口完全拖不动（外框正常亮）；
「按住左键等一会儿再移动」正常。→ **唯一差别：触发键到 200ms 阈值之前鼠标有没有已经在动。**

## 机器化复现
`work/inpute2e/InputE2E.cs` 新增 `tap` / `taphold` / `fastmove` / `user` 模式与「直连现有实例」（exe 传 `-`）。
- `fastmove`（Enter → 20ms → 左键 → 不等，立刻逐帧移动）= **+0,+0**，完整复现。
- `taphold` / `simult` / `sequ` = +150,+60 正常。

## 真凶（现场日志 21:07:47）
```
[诊断] 鼠标键按下 键=0 触发[按住=True 激活=False] 缓冲=False … 坐标=850,530
[诊断] 激活瞬间清点缓冲 缓冲[True,…] 阈值期按住[True,…] 已放行[False,…] 物理按下[False,False,False]
[诊断] 鼠标键抬起 键=0 触发[按住=True 激活=True] … 拖动中=False
```
左键按住 600ms、缓冲账里有那条按下，但 **`GetAsyncKeyState(VK_LBUTTON)` 报 False**。
老代码在激活瞬间有 `if (!IsButtonPhysicallyDown(i)) { _bufferedDown[i]=false; continue; }`
→ **把刚收到、还热乎的缓冲按下当成"用户已松手"整条丢掉**；之后每次移动又被 `AdoptHeldButtonIfAny`
里同一个查询挡回去 → 拖动永远建不起来，外框照旧亮着。这就是「外框被样式包围却拖不动」。
「等一会儿再移动」走的是另一条分支（激活后才按下 → `HandleButtonDown` 直达），不经过这道被污染的关卡。

## 修复（`work/fixed/HoldDrag.cs`，累计 50 hunk）
1. `AdoptBufferedButtonsNow`：删掉 `IsButtonPhysicallyDown` 那道关卡（缓冲账有就直接收养）。
2. `AdoptHeldButtonIfAny`：判据改成**只看三本账**（`_bufferedDown || _heldDuringHold || _passedDown`）；
   自有窗口控件让路逻辑保留。
3. `FlushBufferedClicks`：`keepDown` 改为按账本判定（= true），补"按下"不补"抬起"。
4. `OnTriggerDeactivated`：若仍在拖动立刻 `_drag.End()`（抬起事件丢失兜底）。
5. 诊断长期保留：`[诊断] 鼠标键按下/抬起`、`[诊断] 激活瞬间清点缓冲`、`FindTarget 没找到目标` 改为无条件记录。
   （"物理按下"一栏仅留痕，不参与判定。）

## 验证
- 自检新增 **T88**（两条断言组：A 激活前已在移动；B 复刻 GetAsyncKeyState 漏报+账本有按下）→ **Debug 694/694、发布版 694/694**。
- 真实链路 E2E：`fastmove` **+0,+0 → +200,+80**，从激活那一步起逐帧严格 +25,+10 跟手。

## 两个必须记住的坑
- ⚠️ **本程序有单实例互斥**（`Mutex Local\HoldDrag.SingleInstance.v1`，只对 `--selftest`/`--windowhost` 等分支放行）。
  桌面旧实例还活着时，新起的测试进程会**启动即退出**（日志「已有实例在运行，通知它把设置窗口显示出来」），
  而且旧实例排在钩子链更前面会吞掉 Enter 按下 → 所有 E2E 结果都变成"在测旧实例"。**做真实链路验收前必须先让旧实例退出。**
- ⚠️ **`IsButtonPhysicallyDown()`（`GetAsyncKeyState`）在本进程会漏报**（注入输入尤其明显）。
  任何形式的「按键是否还按着」判断都只能用**钩子事件账本**，不要用它。
- ⚠️ `InputE2E` 的抬起注入**不能带坐标**（`MOUSEEVENTF_MOVE`），否则会把光标拽回去、污染窗口位移读数。
- ⚠️ 给被测 exe 加 `--verbose` 会让每次鼠标移动都写日志，钩子回调被拖慢、激活检测推迟（激活从 200ms 漂到 ~420ms），
  量位移时不要开。
