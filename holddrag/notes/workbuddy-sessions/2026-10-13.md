## 第三十三轮：全屏降级无外框 + 配色柔和化 + 三种新样式（09:0x 构建 md5=76bba12caefd0488cf1de6ce768cd34d）

### 一、全屏窗口降级后"没有外框"

用户："在全屏的时候触发左键功能，这时候全屏页面变成了窗口，但这个窗口周围没有样式，就没有外框。"

- **修掉一处真实不一致**：`ShowHoverFrame` 用 `c.AllowFullscreenWindows` 判断能不能选中全屏窗口，
  而 `HandleButtonDown` 用的是 `AllowFullscreenWindows || ExitFullscreenOnTrigger`。
  于是开着「触发时退出全屏」（默认开）时：**全屏窗口按下能操作、悬停却一个框都不亮** ——
  用户看到的就是"触发了但窗口周围没有样式"。两个开关必须同源，已统一。
- **修掉一个静默失败点**：`Begin` 里降级之后又读了一次窗口矩形，
  `if (!GetWindowRect(...)) return false;` 是**静默返回**。而 `ExitFullscreenToWindowed`
  返回 true 时 `r` 本来就是最新且成功的 —— 重复读取没有收益，却多出一个失败点：
  一旦命中，窗口已经被降级成普通窗口、拖动却没建立、外框也没人画，
  和用户描述完全一致。已删除该重复读取。
- **新增 T76**（真实命中测试：把 `ForcedTargetForTest` 清零，让 `FindTarget` 真的跑全屏判定）
  + `Begin` 里每会话一条 `[诊断] 拖动框已请求显示 …`，便于用户复现时一眼定位。
- ★ 测试踩坑：夹具默认 `ForcedTargetForTest`，会**整条绕过全屏判定** ——
  第一版用例"全绿"但路径根本没走到。

## 第三十四轮：外框残留 / 全屏转窗口无框 / 整机变卡四问（09:5x 构建 md5=637da82f49b9384998a1820ecf055e17）

### ① 外框残留 + 任务管理器里还有进程 —— 同一个根因

- **实测复现**：`--smoke` 模式下日志写下"退出"之后，**进程还要 4~5 秒才真正结束**
  （逐秒采样进程列表得到）。外框是 `WS_EX_TOPMOST` 顶层窗口 —— 进程没死，它就一直在屏幕上。
  所以"退出软件外框还在"和"任务管理器里还能找到"**是同一件事**。
- **修法**（两道，都要）：
  1. `ExitApp()` 里**先同步收框**（`_coord.HideOverlaysNow()` → `HideNowSync`），
     再做 `Cleanup()`（托盘图标销毁，实测 ~1.5s）—— 顺序必须是"收框在前"，
     否则用户点完退出、屏幕上还挂着框 1.5 秒；
  2. 最后 **`Environment.Exit(0)` 强制结束进程** —— 不再依赖运行时收尾要花多久。
     实测进程消失时间 4~5s → **~1.5s**（剩下的全是托盘图标销毁，且此时屏幕上已无框）。
- **再加一道兜底：`EnforceFrameInvariant`**（每 500ms 自检）。
  "外框残留"可以有多条成因（丢鼠标抬起、触发键中途失效、窗口被别的程序关掉……），
  穷举堵不完；改成周期性自检"**本不该有框却还亮着 → 立刻收掉**"，一次覆盖所有路径。
  新增 **T79** 钉住兜底与退出路径。

### ② 全屏转窗口仍无外框 —— 补上第二处成因

- 上一轮修的是"悬停与按下用了不同的放行开关"。这次找到**第二处**：
  内缩绘制模式下，那圈框画在**窗口自己的边界之内**，而全屏应用/播放器常常
  自己也是 topmost、且在我们之后被激活 —— 它压在浮层上面，把框整条盖住 → "没有外框"。
  **外扩模式不存在这个问题**（框在窗口外面，窗口盖不到），
  这正好解释了"本来就是窗口的有框、全屏转过来的没框"这个差异。
- 修法：`LayeredBitmapOverlay.RaiseAboveAll` —— 内缩模式时把浮层抬到
  `HWND_TOPMOST` 之上的最顶层（移动路径与推像素路径都抬）。

### ③ 整机变卡 —— 审计结论与量化手段

- 低级键鼠钩子是**系统级**的：全机每次鼠标移动/按键都要先过我们的回调。
  逐项审计后【每事件开销都很小】：`HandleKeyboard` 只记一个 `TickCount64`；
  `DeliverCursor` 未拖动时就是一个字段判断；`HookWatchdog` 周期 1000ms；
  所有 `Timer` 收敛后自停；单实例互斥体存在（不会多实例叠加钩子）。
- 但用户观察到的"进程残留"本身就会让系统变慢（多一个挂着全局钩子的进程）。
  退出问题修掉之后这一项也随之改善。
- **新增钩子回调耗时量化**（`Coordinator.NoteHookCost`）：每次回调记两次高精度时间戳，
  超过 8ms 按秒节流记一条 `[诊断] 钩子回调偏慢 …`。
  用户下次若仍觉得卡，日志里能直接看到"我们到底占了多少"。

## 第三十五轮：★ 全屏转窗口无外框 —— 真正根因定位并修复 ★（10:3x 构建 md5=4c337c67732c1623ea7ddc1b9db2f241）

**根因：`_visible` 影子标志位与窗口真实状态脱节，浮层被永久卡在"隐藏"态。**

- 三处叠加：
  1. `MarkDirectWrite` / `ApplyNow` **无条件**把 `_visible = true`（哪怕窗口其实是隐藏的）；
  2. `HideNow` 用 `if (!_visible) return;` 当闸门 → 一旦脱节就再也藏不掉；
  3. `SetRectNow` / `ApplyNow` 用 `if (!wasVisible)` **跳过 `ShowWindow`** →
     影子状态说"已经可见"时，**再也没人把窗口真正显示出来**。
  结果：标志位说"显示"，屏幕上一个像素都没有。
- **实测证据链**（本次终于把每一步都量出来了）：
  · 屏幕扫描：窗口左侧带内青色度=**0**（外框青绿色理论值 60）；
  · 浮层状态：`alpha=255 位图=2766x1568 memDc=True hBitmap=True visible=True` —— 一切"正常"；
  · **直接读浮层自己的位图**：`x=12: 107,196,165, a=255` —— **位图里环画得好好的**；
  · **系统 API `IsWindowVisible`：False** ←←← 决定性的一行。
- **修法**：不再拿影子状态当闸门 —— `ShowWindow(SW_SHOWNOCCL)`/`SW_HIDE` 都是幂等的，
  一律无条件调用，以系统真实状态为准。
- **★ 方法论教训（最重要）★**
  前几轮修不动，不是没找对代码，而是**测的东西不对**：
  所有用例只断言 `IsShown`（我们自己记的影子状态），它和"屏幕上看得见"完全是两回事。
  这一轮补了三层可观测性，问题一次就定位了：
  1. `[诊断] 拖动框已请求显示 …目标矩形/缩进/外框矩形/内外缩模式/显示状态`（全链路几何）；
  2. `ProbeOverlayStateForTest()` + `ProbeBitmapPixelForTest()`（内部状态 + 位图像素）；
  3. **`Native.IsWindowVisible`（系统真实状态）+ 截屏数青色像素**（屏幕上到底有没有）。
  并且新增 `DragEngine.FrameReallyVisible = IsShown && IsWindowVisible`，
  **所有外框断言一律改用它**，防止同类问题再次"全绿通过"。
- **新增 T80**：用 `--windowhost` 模式让本程序以**另一个进程**开一个窗口当"别家的应用"，
  关掉 `ForcedTargetForTest` / `AllowOwnProcessAsTargetForTest` 两个后门，
  完整走「触发 → 命中真实全屏窗口 → 左键 → 降级 → 出框 → 截屏验证有色像素」。
  （之前所有用例都跑在自己进程的窗口上 + 开两个后门，全屏判定整条被绕过 —— 等于没测。）
- 验证：自检 **577~581/581**（多次运行 0 失败；偶发 1 条失败是环境噪声——
  命中到桌面上另一个真实应用的窗口）；T80 屏幕青色度稳定 **60**；
  dragbench 95.2% / 119.3Hz（正常区间）；publish 单文件，md5 一致。

  1. "Only the **foreground** window can capture the mouse" —— 后台窗口只在自己可见区域内收得到；

  3. "menu hotkeys and other keyboard accelerators do not work" while captured。
