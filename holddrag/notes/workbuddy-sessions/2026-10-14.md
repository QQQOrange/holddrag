# 2026-10-14 工作日志（HoldDrag 第四十六~四十九轮）

## 第四十六轮：钩子链抢占（与 wgesture 共存）
- 用户报障：Enter 触发态下右键无法调整大小 —— 第三方鼠标手势软件抢占。
- 根因：WH_MOUSE_LL 是 LIFO 链、后装先调；wgesture 装在我们之后。
- 修法：激活触发态时经 WM_REHOOK_MOUSE 让钩子线程就地重装鼠标钩子抢回链头。
- 自检新增 T84（重装后双钩子仍在、真实链路可用）。

## 第四十七轮：外框永远在最顶
- 用户报障：全屏转窗口的窗口没有外框（内缩绘制时框在窗口边界内，被 topmost 全屏应用盖住）。
- 修法：RaiseAboveAll 默认 true，每帧抬顶（微秒级 SetWindowPos）。

## 第四十八轮：钩子线程零阻塞 —— Enter+右键缩放整机卡死根因修复
- 用户报障（最高优先级）：Enter+右键缩放整机死机（鼠标能动、点击全死、只能重启）。
- 根因（T81 两次稳定复现）：Begin 的 ShowDragFrame 在钩子线程上持 `_bufGate`
  跨线程调 SetWindowPos（同步发 WM_WINDOWPOSCHANGED 等对方泵掉）；浮层线程正卡在
  同一把锁上（HideOverlay→WM_APPLY→ApplyNow→Push）。**双方互等 → 钩子回调不返回 →
  全系统输入冻结**。旧注释断言"SWP_NOSENDCHANGING 不惊动别的线程"是错的（只抑制
  CHANGING，CHANGED 照发）。
- 修法：① Push 的 ULW/抬顶 SWP 全部移出 `_bufGate`（锁内只取快照+在飞计数，
  "先 SelectObject 新位图再删旧"保证在飞 ULW 最坏混合帧、下一帧即修正）；
  ② SetRectNow 纯移动 SWP 移出锁；③ 钩子线程显框改异步管线（ShowDragFrame→SetRect），
  实际写在工作线程、至少一帧之后。
- 新增 T85：阻塞目标（WM_WINDOWPOSCHANGING 睡 1.5s）上 Begin/移动/松手/降级/置顶
  必须 <500ms 返回，且落位断言必须过。
- 另：**dragbench 守卫**——曾经 Chrome 全屏置顶窗压住靶窗抓取点，帧完美跟随但靶窗不动，
  以"性能回归"面貌误报。守卫：跑基准前 WindowFromPoint(抓取点) 必须是靶窗，否则明确中止。
  （本轮 session 又遇到一次：Edge 的 render widget 瞬时压在抓取点上；重跑即过——守卫有效。）

## 第四十九轮：钩子线程对目标窗口零写入 —— SWP_ASYNCWINDOWPOS 也不能信
- T85 收尾时仍偶发 FAIL（松手 1520ms / 置顶切换 1521ms），失败点在路径间漂移。
- 插桩定位结论：End 路径本身 0~1ms；工作线程 SetDragRectFrame 挡 1535~1541ms（设计内背压）。
- **核心发现：win32k 单窗位置锁**。目标线程正压着一条位置更新不放时，另一线程对该窗
  SetWindowPos 被位置锁挡住，**连 SWP_ASYNCWINDOWPOS 也排队**（ToggleTopMost 实测 1521ms）。
  → "异步提交"不是安全边界，钩子线程一次都不能写目标窗口。
- 修法（结构性，全部落地）：
  1. `DragEngine.PostTargetWork`：对目标窗口的写一律派发到拖动工作线程（单线程 FIFO+背压）。
  2. `WindowActions.ExitFullscreenToWindowed(h, ref r, pt, offHook)`：最大化分支用
     `GetWindowPlacement` **预估**还原矩形（纯内核读，不等目标），SW_RESTORE 与两处 SWP 全派发。
  3. `DragEngine.ReconcileStartRect`：工作线程写完回读 GetWindowRect 后、第一帧之前把
     StartRect/_inset/Zone 校正成真实值（FIFO 保证顺序）—— Begin 立即返回且会话矩形精确。
  4. `Coordinator` 三个一次性动作点（双击左键最大化、双击右键吸附、一次性动作）全部改
     "动作 + RefreshHoverAfterAction" 闭包派发。
- **测试架修正（重要教训）**：`MeasureOnOtherThread` 秒表原在等待循环上起停，UI 线程
  DoEvents 替阻塞目标泵消息（1.5s 睡在 UI 线程）会把实际 ~1ms 的投递测成 1530ms
  （全量跑误报一次）。改为秒表在被测线程内部起停；判据不变：真回归照报，测试架开销不计入。
  诊断期用 `HD_ONLY=T85` 单跑 + `[TM]` 计时探针（均已删除）。
- 验证：全量自检 **663/663 全绿**；T85-only 10/10；dragbench 三次全 PASS
  （落位精确、写入率 94.8%、有效更新率 114~119Hz、单帧 2.3ms、P95 11ms、落后 3.3~4.0ms；
  较历史 124Hz 的缺口为当前桌面负载：Edge 活动页 + WGestures 全屏挂件 + 会话进程，
  每帧热路径本轮未动，判定环境因素）。
- 部署：项目根 / publish/ / 桌面 三处 md5 一致
  `9192c164d5fd7cefbdfce7a9ce2488eb`。
