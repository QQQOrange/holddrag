T69 / T80 两条用例的「假红」根因（第三轮验证时定位）
==================================================================

【T69 外框不透明度：40% 必须明显比 100% 淡】
旧判定：num3 < num2 * 0.6      （num2=100% 时的屏幕青色度，num3=40% 时的）

机理：外框是半透明浮层，屏幕读数 = alpha×外框色 + (1-alpha)×背景。
      固定阈值等价于假设「背景远比外框暗」。本机壁纸是深青，实测采样带像素
      (RGB 4,70,91) → 青色度 23（greenness 定义 = G - (R+B)/2，见 BandMaxGreenness）。

三次观测与公式逐一吻合（外框 100% 读数为 60）：
  背景 bg= 8  →  理论 0.4*60+0.6*8  = 28.8  →  实测 29  →  旧判定通过
  背景 bg=23  →  理论 0.4*60+0.6*23 = 37.8  →  实测 36  →  旧判定【假红】
  背景 bg=37  →  理论 0.4*60+0.6*37 = 46.2  →  实测 44/46 → 旧判定【假红】
结论：产品渲染完全正确（混合比例就是 40%），是用例的固定阈值写错了。

改法：先在外框还没亮时量同一带背景 bg，再断言
      (a) num3 <= int(0.4*num2 + 0.6*bg) + 4      —— 读数与混合公式吻合
      (b) num2 - num3 >= (num2 - bg) / 2          —— 至少削掉一半「外框−背景」对比度
      改后背景为 10 / 23 / 38 三种取值下均通过（Debug 3 次 + Release 3 次全绿）。

实测采样（自检输出原文）：
      loop3_1: （不透明度）带内青色度 100%=60  40%=46
      loop3_4: （不透明度）带内青色度 背景=23  100%=60  40%=36（混合上限 41）
      loop3_6: （不透明度）带内青色度 背景=38  100%=60  40%=44（混合上限 50）
      rel4: （不透明度）带内青色度 背景=10  100%=60  40%=28（混合上限 34）
      ab_r3_1: （不透明度）带内青色度 背景=10  100%=60  40%=28（混合上限 34）

【T80 用外部进程的真实全屏窗口走真实链路】
旧代码：SetWindowPos(num, ..., 20u)，20 = SWP_NOACTIVATE | SWP_NOZORDER
        → 测试窗口既不激活也不置顶，桌面上任何同层窗口都能盖住它。

实测本机桌面中心的顶层窗口（WindowFromPoint，物理坐标）：
  屏幕中心 (1920,1080) → h=0x207AC "Get FREE ocr api key 和另外 7 个页面 - 个人 - Microsoft Edge"
  自检失败时打印的命中 h=0x3C151E "QS-噪声画面|987x725|15,131,127|0.005"
  物理矩形 398,227 2004x1535 —— 正好覆盖屏幕中心，来源为 Microsoft Edge。
结论：FindTarget 返回「压在最上面的窗口」本来就是正确行为；是用例前提（全屏窗口在指针下）
      没有真正成立。

改法：
  1) SetWindowPos(..., 0x0040u /*SWP_SHOWWINDOW*/) 且 hWndInsertAfter = HWND_TOPMOST(-1)
     —— 真实的全屏窗口本来就在最前，让前提真的成立；
  2) 加前置校验：命中 != 测试窗口时明确「跳过」并打印原因，不据此判产品对错。
