## 一、产品目标

### 1.1 要解决的问题

Windows 原生拖动窗口只有两条路：拖标题栏，或者先按 `Win + 方向键` 做吸附。
对以下几类场景都不好用：

1. **窗口很大或标题栏在屏幕外** —— 想挪一下，光标得先跑很远去找标题栏。
2. **全屏 / 无边框窗口** —— 根本没有标题栏可拖。
3. **需要精细对位** —— 鼠标在标题栏、眼睛却要盯着窗口内容，来回换焦点。
4. **不想记 Win 键等系统手势** —— 希望"随手一拖"，不改动肌肉记忆。

### 1.2 产品目标（P0）

| 编号 | 目标 | 可判定结果 |
| --- | --- | --- |
| G1 | 在**光标所在位置**直接拖走窗口，不需要找标题栏 | 光标停在窗口任意非交互区域，长按触发键后按住左键，窗口 1:1 跟随光标位移 |
| G2 | 触发方式可自定义且**不破坏日常打字** | 默认 Enter；短于阈值松手时，原按键由 `SendInput` 原样补发（换行、提交、确认均正常） |
| G3 | 用同一套"长按"手势承载三种鼠标键动作 | 左键 = 移动、右键 = 九宫格缩放、中键 = 一次性动作，三键均可各自改绑九种动作之一 |
| G4 | 触发瞬间给出明确的**接管反馈** | 长按到达阈值那一刻，光标下的窗口四周亮起圆角外框（可关），移动光标时外框跟随 |
| G5 | 绝不误伤窗口内容与宿主界面 | 光标落在自家设置页的可交互控件上时不接管；`GroupBox` 等容器仍可整窗拖走 |
| G6 | 拖动跟手，不掉帧、不滞后、不抖动 | 真实输入链路上逐帧位移与光标位移 1:1；外框与窗口零滞后；贴边/出屏时外框几何恒定 |
| G7 | 钩子被系统或第三方摘除后能自愈 | `HookWatchdog` 每秒巡检，连续 3 次判定异常即自动重装，托盘菜单可见恢复次数 |
| G8 | 长用不涨资源 | 320 次完整拖动后 GDI / USER / 句柄 / 私有内存峰值增量不超过阈值（`--stress` 断言） |

### 1.3 非目标（明确不做）

| 编号 | 不做的事 | 原因 / 边界 |
| --- | --- | --- |
| N1 | Win11 Snap Layouts 布局面板 | 系统原生拖动循环与"双击左键/右键"互斥，本产品自研吸附，落点与原生一致但不能唤起系统面板 |
| N2 | 按住触发键连续换行 | 「长按」与「连发」原理上互斥，必须吞掉键盘自动重复 |
| N3 | 拖到屏幕边缘自动半屏 / 与其它窗口对齐 / 落点预览 | 该整组功能已在 #32 决策中整体下线，配置项 `EdgeSnap` / `SnapToOtherWindows` / `SnapPreview` / `SnapDistance` 均已移除，且由自检 `T29` 断言"无残留" |
| N4 | 拖动期窗口半透明 / 尺寸提示 | 同上，`DragTransparency` / `DragSizeHint` 已移除 |
| N5 | 移动鼠标即改变窗口位置（无需按键） | 本产品语义始终是"按住触发键 + 按住鼠标键才拖" |
| N6 | 修改或替换上游 AltDrag 的 C 源码 | 上游文件按原样保留，C# 实现为独立交付物 |

## 二、名词与状态机

### 2.1 术语

| 术语 | 定义 |
| --- | --- |
| 触发键 | 用户指定、用于进入"可拖"状态的键（默认 `Enter`，键标识 `K:0x0D`） |
| 长按阈值 | `HoldMs`，默认 600 ms，可调 100–3000 ms（步进 50） |
| 按住阶段 | 触发键已按下但未达阈值。此时鼠标键按下会被**缓冲**，不投递给下层窗口 |
| 激活态 | 触发键按住时长达到阈值。此时外框亮起，鼠标键动作生效 |
| 拖动会话 | 激活态下按住左/右键并开始移动后建立的会话，含起始光标点、起始窗口矩形、缩放区 |
| 外框 | 标记"当前接管窗口"的分层浮层窗口，窗口类 `HoldDragOverlayWindow` |
| 账本 | 钩子事件账本：收到按下且未收到配对抬起即视为仍按住。**判据只用账本，绝不用 `GetAsyncKeyState`** |
| 合成事件标记 | 本程序自己注入的事件带 `dwExtraInfo = 1215261796`（MagicExtraInfo），据此与真实输入区分 |

### 2.2 触发键状态机

```
                 按下                          达到 HoldMs
     空闲  ───────────────▶  按住阶段  ─────────────────────▶  激活态
       ▲                      │   │                              │
       │   阈值内松手：        │   │ 阈值内按下鼠标键：            │ 松开触发键：
       │   SendInput 补发      │   │ 记入缓冲账，不投递            │ 立即退出；若仍在
       │   完整"按下+抬起"     │   │                              │ 拖动则 End()
       └──────────────────────┘   └──────────────────────────────┘
                                    缓冲账在激活瞬间被收养
                                    （AdoptBufferedButtonsNow）
```

关键约束：

- **短按必须透传**：阈值内松手，用 `SendInput` 合成一次完整的「按下 + 抬起」补发，日常打字不受影响（仅极微小延迟）。
- **长按必须吞掉自动重复**：因此"按住不放连续换行"会被压成一次（见 N2）。
- **`RequireHold` 关闭时**：按住即生效，短按也不再补发原按键（该键被彻底占用）。
- **激活瞬间必须收养缓冲**：阈值内被缓冲的鼠标按下，在激活那一刻立即收养，不许等"激活后的第一次鼠标移动"。
- **同刻松手要清账**：收养前查账本；查 `IsPointOverOwnInteractiveControl` 决定是否还给控件。
- **抬起事件丢失兜底**：`OnTriggerDeactivated` 若发现仍在拖动，立刻结束会话。

### 2.3 鼠标键判定优先级（激活态下，按下瞬间）

按顺序短路判定，任一命中即不再向下走：

1. 光标落在**本进程自有窗口的可交互控件**上 → 完全放行给控件（不接管、不吞）。
2. 双键组合语义保护（例如已选中文字后再按触发键）→ 不接管。
3. 命中黑名单 / 排除类 / 不可见 / 最小化 / 无 `WS_VISIBLE` 的窗口 → 放行。
4. 全屏（或无边框）窗口且 `AllowFullscreenWindows = false` → 放行（默认跳过）。
5. 全部通过 → 接管：吞掉本次按键，进入拖动会话或执行一次性动作。

### 2.4 拖动会话与坐标

- 起始矩形取按下瞬间的窗口矩形；起始光标点取按下点。
- 移动：`目标矩形 = 起始矩形 + (当前光标 − 起始光标)`。
- 缩放：先由 `Zones.Resize` 判定九宫格（角格比例 `CornerPercent`，默认 26%，范围 5–45），
  命中中心区则退化为"最近的那个角"；只拖判定命中的那几条边。
- 窗口最小尺寸不取自应用，取系统 `SM_CXMIN` / `SM_CYMIN`，并分别兜底为 ≥64 / ≥32。
- 坐标空间：进程内统一到 `CoordSpace`（`PerMonitorV2` 感知；实测非感知时用 `SetProcessDpiAware` 抢救）。

## 四、功能边界

### 4.1 触发键支持范围

| 类别 | 支持 | 备注 |
| --- | --- | --- |
| 字母 / 数字 / 功能键 / 方向键 / Enter / 空格 / CapsLock / Win 键 | ✅ | 键标识 `K:0x<VV>`，例如 `K:0x0D` = Enter |
| Alt / Ctrl / Shift | ✅ | **区分左右**：`K:LAlt` / `K:RAlt` / `K:LCtrl` / `K:RCtrl` / `K:LShift` / `K:RShift` |
| 鼠标侧键（前进 / 后退） | ✅ | 键标识 `M:1` / `M:2` |
| 鼠标左键 / 右键 / 中键 | ❌ | 已被鼠标动作占用，不能当触发键 |

已知代价（用户须知情）：

1. 用 `Alt` / `Ctrl` / `Win` 作触发键时，按住期间该键的组合功能不可用（如 Win 作触发键时 `Win+E` 无效）。
2. 用 `CapsLock` 作触发键时不会切换大小写（被程序压制）。
3. 按住触发键不会连续换行（见 N2）。

### 4.2 鼠标键动作（九种）

| ID | 名称 | 类型 |
| --- | --- | --- |
| `Move` | 移动窗口 | 拖动类 |
| `Resize` | 调整大小 | 拖动类 |
| `Maximize` | 最大化 / 还原 | 一次性 |
| `Minimize` | 最小化 | 一次性 |
| `Close` | 关闭窗口 | 一次性（有误触风险） |
| `Lower` | 置于最底层 | 一次性 |
| `AlwaysOnTop` | 置顶 / 取消置顶 | 一次性 |
| `Center` | 在屏幕上居中 | 一次性 |
| `Nothing` | 不绑定动作 | 该键恢复原始功能 |

- 拖动类动作在 `Begin` / `End` 内自带"收起环形框 → 换分层框 → 重新亮框"的完整流程。
- 非拖动的一次性动作必须在动作后**重新亮回外框**，并强制失效悬停缓存（因为动作常刚改过窗口矩形）。

### 4.3 缩放（九宫格）与吸附（九宫格→屏幕）

缩放判定九宫格：

```
 ┌───────────────┬───────────────┬───────────────┐
 │    左上角      │      上       │    右上角      │
 ├───────────────┼───────────────┼───────────────┤
 │      左       │    中心区     │      右       │
 ├───────────────┼───────────────┼───────────────┤
 │    左下角      │      下       │    右下角      │
 └───────────────┴───────────────┴───────────────┘
```

- 命中角格 → 同时拖两条边；命中边格 → 只拖那一条边；命中中心区 → 自动选**最近的那个角**。
- 角格占比 = `CornerPercent`（默认 26%，5–45）。

双击右键把同一套九宫格映射到屏幕：

| 格 | 落点 |
| --- | --- |
| 上 | 上半屏 |
| 下 | 下半屏 |
| 左 | 左半屏 |
| 右 | 右半屏 |
| 左上 / 右上 / 左下 / 右下 | 对应四分之一屏 |
| 中心区 | 最大化 |

**边界**：仅贴屏幕下边缘不吸附（与 Windows 原生 Aero Snap 一致）；吸附只在**当前显示器工作区**内计算；Win11 Snap Layouts 面板不弹出（见 N1）。

### 4.4 黑名单

- 匹配对象：窗口**类名**、窗口**标题**、**进程 exe 名**（如 `notepad`），三者任一命中即生效。
- 匹配方式：**忽略大小写的子串匹配**，逗号分隔多个关键字。
- 长度上限：2000 字符（超长截断）。
- 命中后果：**完全不接管**（按键原样给下层窗口）。
- 便捷入口：`选择程序…`（挑 exe）、`点选窗口`（屏幕上直接点）。

### 4.5 窗口排除规则

**永不接管**的内置类（18 个，精确匹配、区分大小写）：

`Progman`、`WorkerW`、`Shell_TrayWnd`、`Shell_SecondaryTrayWnd`、`TaskListThumbnailWnd`、
`ForegroundStaging`、`Windows.UI.Core.CoreWindow`、`ApplicationManager_ImmersiveShellWindow`、
`MultitaskingViewFrame`、`XamlExplorerHostIslandWindow`、`TopLevelWindowForOverflowXamlIsland`、
`Windows.Internal.Shell.TabProxyWindow`、`EdgeUiInputTopWndClass`、`SysShadow`、
`tooltips_class32`、`MSCTFIME UI`、`IME`、`Default IME`。

**自有窗口内可交互控件**（指针在其上时放行，17 个基础类名 + `RichEdit*` 前缀）：

`msctls_trackbar32`、`Edit`、`Button`、`ComboBox`、`ComboBoxEx32`、`msctls_updown32`、`ScrollBar`、
`msctls_progress32`、`ListBox`、`SysListView32`、`SysTreeView32`、`SysTabControl32`、
`msctls_statusbar32`、`ToolbarWindow32`、`SysMonthCal32`、`SysDateTimePick32`、`SysIPAddress32`。

两条硬约束：

1. WinForms 会把系统控件类名包装成 `WindowsForms10.<基础类名>.app.<版本>_r<n>_ad<n>`，
   比对前必须先剥掉 `WindowsForms10.` 前缀并截到下一个 `.` 之前。
2. `GroupBox` 的窗口类就是 `BUTTON`，必须再判定样式位 `(GWL_STYLE & 0xF) == 0x7 (BS_GROUPBOX)`
   才能与真按钮区分；否则设置页里成片的分组区会把"拖整窗"整个吃掉。

其它拒绝条件：窗口不可见 / 无 `WS_VISIBLE` / 是 `WS_EX_TOOLWINDOW`（`0x80`）/ 矩形宽或高 ≤ 0 /
属于本进程但不是合法自有窗口（浮层 `HoldDragOverlayWindow`、探针类 `HoldDrag.Probe.Target` 永远排除）。

### 4.6 全屏 / 最大化窗口

| 场景 | 行为 |
| --- | --- |
| `AllowFullscreenWindows = false`（默认） | 命中全屏窗口时**跳过**，按键放行 |
| `AllowFullscreenWindows = true` | 允许拖动全屏 / 无边框窗口（游戏、全屏播放器可能不重画，有风险） |
| `ExitFullscreenOnTrigger = true`（默认） | 触发时先把全屏 / 最大化窗口变回普通窗口再执行拖动或缩放；降级后外框必须重新出现在新窗口周围 |
| `RestoreMaximizedWhenMoved = true`（默认） | 拖动已最大化窗口时先还原再拖 |

"全屏"判定：窗口矩形同时覆盖所在显示器的 `rcMonitor` 四条边（左、上、右、下）。

### 4.7 晃窗最小化

| 参数 | 值 |
| --- | --- |
| 判定窗宽 | 800 ms |
| 最小跨度 | 32 逻辑 px |
| 最大跨度 | 220 逻辑 px |
| 需要往复次数 | 4 |
| 最大净漂移 | 80 逻辑 px |
| 最小路径长度 | 150 逻辑 px |
| 水平优势 | 0.72 |
| 冷却 | 900 ms |
| 采样上限 | 768 |

两次之间必须"多次往复 + 净位移接近 0"，因此正常拖动不会被误触发；再晃一次还原全部被最小化的窗口（还原名单持久记录）。

### 4.8 流畅度与节流

- `Auto`：按实测显示器刷新率节流，界面显示实测 Hz 与每帧毫秒数；实测不到时不节流。
- `Custom`：0 = 不限制；非 0 时钳到 20–360 Hz。
- 目的：鼠标每秒可产生数百个移动事件，不节流会把目标窗口消息队列塞满
  `WM_WINDOWPOSCHANGING + WM_MOVE + WM_SIZE + WM_PAINT`，这就是"越拖越卡"的来源。
- 写窗口必须异步提交（`SWP_ASYNCWINDOWPOS`），否则"移动/变形不跟手"。
- `MoveRate` / `ResizeRate` 在 `Normalize()` 中恒被强制为 1（内部保留字段，非用户可调项）。

### 4.9 自更新（v1.1 新增）

**触发方式**

| 方式 | 行为 |
| --- | --- |
| 启动自动检查 | 托盘进程启动完成后后台查一次；**只在发现更高版本时**用气泡提示，不打断用户正在做的事 |
| 托盘菜单「检查更新…」 | 打开设置窗口并立刻执行一次检查 |
| 「关于」页「检查更新」按钮 | 立刻检查；无论结果都给明确反馈（含失败原因） |

**版本比较**：从 `releases/latest` 的 HTML 重定向解析 tag（如 `v1.1.0`），
转成四段版本号比较；**仅当远端严格大于当前版本**才视为新版本。
非法/空 tag 一律返回 null，绝不误判。

**不依赖 api.github.com**：匿名调用有速率限制且常被企业网络拦截，
因此改为请求 `releases/latest` 拿重定向 tag，再用固定的
`releases/download/<tag>/HoldDrag.exe` 直链下载。网络异常如实回传，**绝不静默当作"已是最新"**。

**每个新版只提示一次**：提示后在配置里记下 `LastUpdateNotified`，
同一 tag 不再重复弹窗；写该字段时**只 `Save()` 不走 `Apply()`**，
避免触发 `OnConfigChanged → _drag.Cancel()` 掐断用户正在进行的拖拽。

**下载**：后台线程流式下载到 exe 同级目录的 `HoldDrag-update.download`
（先写 `.part` 再改名，避免半截文件）；校验 Content-Length，
不完整或 0 字节即判失败；进度回显在「关于」页状态文字上。

**替换机制（关键）**：本机实测确认——**Windows 允许重命名一个正在运行的 exe，
也允许把新文件移到它名下；唯一做不到的是删除正在运行的旧文件**。因此：

1. 旧 exe → `HoldDrag.exe.old`（正在运行也允许）
2. 新文件 → `HoldDrag.exe`（成为用户双击的那个名字）
3. 拉起新 exe 并把 `.old` 路径作为 `--updated-from` 参数传给它
4. 新版本启动后删除 `.old`（此时旧进程已退出，删除必然成功）

全程**不使用批处理替换器**，且第 2 步失败会把旧文件改回来，保证任何时候都有一份可运行的 exe。
更新就绪后必须**退出整个托盘进程**（而不是只关设置窗口），否则 exe 文件一直被占用、替换无法完成。

**失败兜底**：每一步失败都提示具体原因、给出发布页链接，并说明已下载文件的存放位置。

### 4.14 已知限制（必须对外如实告知）

1. Win11 的 Snap Layouts 布局面板不会弹出（见 N1）。
2. 按住触发键不会连续换行（见 N2）。
3. 用 `Alt` / `Ctrl` / `Win` 作触发键时，按住期间该键的组合功能不可用。
4. `CapsLock` 作触发键时不会切换大小写。
5. 极少数自绘界面 / 全屏游戏的窗口可能无法移动或移动异常。
6. 提权窗口只有在本程序也提权时才能操作。
7. **落键次序边界**：若左键按下**早于**触发键 25 ms 以上，那一次按下已真实投递给下层窗口，
   补起时若把起点回溯到按下点会让窗口跳变，故设计上选择"不跳变"→ 丢掉起段位移（实测 `leftfirst` 为 +125,+50 而非 +150,+60）。
   **建议用法：先把触发键落稳，再按左键。**
8. `tap`（点一下触发键即松开）在"按住才拖"的语义下不会拖动；若用户习惯是"点一下抓住"，
   需另加"点一下抓 / 再点一下放"的粘滞模式（**当前版本未实现**，属待定需求）。

### 5.4 真实输入链路端到端（C 类）

被验收对象必须是**正在运行的 exe 本体**，用 `SendInput` 注入真实输入（`dwExtraInfo = 0`），
逐步注入 `MOUSEEVENTF_MOVE` 并逐帧记录目标窗口位移。工具见 `../probes/inpute2e/`。

| 场景 | 期望 |
| --- | --- |
| `simult` / `rightfirst`（触发键先落，左键落在阈值窗口内） | 位移 = 1:1 跟手，不得少走第一步 |
| `sequ`（先过阈值再按左键） | 位移 = 1:1 跟手 |
| `fastmove`（Enter → 20 ms → 左键 → 不等直接移动） | 位移 = 1:1 跟手（**这是 v1.0.0 修复的关键场景**） |
| `nomove`（按下后完全不动） | 窗口不动 |
| `tap`（点一下即松开） | 不拖动（当前语义，见 §4.13-8） |
| `leftfirst`（左键早于触发键 25 ms） | 已知固有边界：丢掉起段位移（见 §4.13-7） |

硬性要求：

- 工具自身必须用 `SendInput(MOUSEEVENTF_MOVE)` 移动光标；**`SetCursorPos` 不产生输入事件**，低级钩子看不到。
- 注入抬起时不得带新的移动标志，否则"抬起本身"会把窗口带到位、污染判定。
- 任何会移动光标的用例结束必须 `SetCursorPos` 还原，否则下一次运行会因光标残留而假红。
- 被测 exe 开 `--verbose` 会拖慢钩子回调（激活从 200 ms 漂到约 420 ms），量位移时不得开启。

**审查中发现并修复的缺陷**（详见提交记录与自检 T89）

| 编号 | 缺陷 | 影响 |
| --- | --- | --- |
| B1 | 替换器把**批处理文本写成 `.exe`** 并用 ShellExecute 启动 | 更新功能**完全无法工作**（旧实现必然报"不是有效的 Win32 应用程序"） |
| B2 | 更新成功后只 `Close()` 设置窗口，**托盘进程不退** | exe 一直被占用，替换永远失败 |
| B3 | 批处理替换器三处硬伤 | 删自身 / 新版可能隐藏启动 / 注释与代码不符 |
| B4 | 自动检查写配置走 `Apply()` | 触发 `OnConfigChanged → _drag.Cancel()`，**掐断用户正在进行的拖拽** |
| B8 | 预览不透明度只在单一开关路径同步 | 拖「不透明度」时预览不刷新，用户以为该参数没生效 |

| B6 | `ResetDefaults` 未保留 `AutoCheckUpdate` | 用户关掉的自动更新被「恢复默认值」悄悄改回开 |

**替换机制的关键结论（本机实测得出，已写入实现与自检）**

> Windows **允许重命名一个正在运行的 exe**，也**允许把新文件移到它名下**；
> 唯一做不到的是**删除**正在运行的旧文件。
> 因此替换走「旧 → `.old`，新 → 正式名，新版本启动后删 `.old`」三步，
> **完全不需要批处理替换器，也不需要等旧进程退出**。
